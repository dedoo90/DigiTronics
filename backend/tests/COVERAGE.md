## Why 0%

All 105 tests exercise the backend as **black-box child processes**
(the real `server.js` booted on an isolated port with an isolated temp
data directory). Jest's native coverage instruments only code loaded
inside the test process itself, so execution inside the child processes
is invisible to it. This is an instrumentation-visibility artifact of
the chosen test architecture — not an absence of test execution:

- 6 suites, 105 tests, all passing
- Live HTTP flows verified: authentication (login/refresh/logout/me/
  permissions/roles), full CRUD + 400/404/stats for Users, Customers,
  Suppliers, Treasury, Employees, synchronization contract (client ids,
  duplicate-push rejection, `_backendId` aliasing, refresh merge,
  conflict timestamps), security (JWT accept/reject/expiry, bcrypt
  storage + legacy migration, hash non-disclosure, rate limiting, schema
  validation, prototype-pollution stripping, malformed JSON, role-based
  authorization under `AUTH_REQUIRED=true`)

## Note

A child-process-aware measurement (V8 coverage via `NODE_V8_COVERAGE`)
was explored and abandoned per project direction; Jest native coverage
is the configured reporting path. If line-level numbers are ever
required, the options are an in-process app export (requires a
`require.main` guard in `server.js`) or V8 coverage merging with a
graceful IPC shutdown (the helpers already shut children down cleanly
over IPC in `tests/helpers/testServer.js`).
